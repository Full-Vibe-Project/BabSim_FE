# 프론트엔드 테스팅 컨벤션

## 1. 목표

-   **안정성**: 새로운 코드 변경이 기존 기능을 손상시키지 않음을 보장하는 안전망을 구축합니다.
-   **품질**: 코드의 잠재적인 버그를 사전에 발견하고, 리팩토링을 자신감 있게 수행할 수 있는 기반을 마련합니다.
-   **문서화**: 잘 작성된 테스트 코드는 그 자체로 해당 코드의 요구사항을 설명하는 살아있는 문서가 됩니다.

---

## 2. 핵심 철학: "구현이 아닌 사용자의 경험을 테스트한다"

모든 테스트는 **사용자의 관점**에서 작성됩니다. 우리는 코드의 내부 동작 방식(예: 특정 state의 값)이 아닌, 사용자가 화면에서 보고 상호작용하는 **경험**을 검증하는 것을 최우선 목표로 삼습니다.

> **Bad ❌**: "버튼을 클릭하면 `handleLogin` 함수가 호출되는가?"
> **Good ✅**: "사용자가 '로그인' 버튼을 클릭하면, '환영합니다'라는 텍스트가 화면에 나타나는가?"

이 원칙을 통해 내부 코드를 리팩토링해도 쉽게 깨지지 않는 견고하고 유지보수하기 좋은 테스트를 만듭니다.

---

## 3. 개발 프로세스: TDD (테스트 주도 개발)

우리 팀은 **"레드-그린-리팩토"** 사이클을 따르는 테스트 주도 개발을 지향합니다.



1.  **🔴 레드 (Red)**: 실패하는 테스트 케이스를 먼저 작성하여 기능의 요구사항을 명확히 정의합니다.
2.  **🟢 그린 (Green)**: 작성된 테스트를 통과시키기 위한 최소한의 코드를 작성합니다.
3.  **🔵 리팩토 (Refactor)**: 테스트가 통과하는 상태를 유지하며, 코드의 품질과 구조를 개선합니다.

---

## 4. 테스트 전략: 테스트 피라미드

우리 프로젝트는 아래의 테스트 피라미드 전략을 따릅니다.



### **1) 유닛 테스트 (Unit Tests) - `Vitest`**

-   **대상**: UI나 프레임워크에 의존하지 않는 순수한 비즈니스 로직.
-   **FSD 위치**: `shared/lib`, `entities/model`, `features/model` 내의 유틸리티 함수.
-   **핵심**: 입력값에 따른 출력값을 검증합니다.

### **2) 통합 테스트 (Integration Tests) - `Vitest` + `RTL`**

-   **대상**: **우리 테스트의 핵심 (80% 이상).** 실제 DOM에 렌더링되는 React 컴포넌트.
-   **FSD 위치**: `entities/ui`, `features/ui`, `widgets/ui`의 모든 컴포넌트.
-   **핵심**: 사용자의 상호작용에 따라 컴포넌트가 예상대로 반응(화면 변경)하는지 검증합니다.

### **3) E2E 테스트 (End-to-End Tests) - `Playwright`**

-   **대상**: 사용자의 핵심 비즈니스 시나리오 (회원가입, 로그인, 글쓰기 등).
-   **핵심**: 최소한으로, 하지만 가장 중요한 기능 흐름만 테스트하여 서비스의 핵심 기능이 정상 동작함을 보장합니다.

## 5. 정확한 테스트 작성법

### **5.1. AAA (Arrange-Act-Assert) 패턴**

모든 테스트 케이스는 **준비-실행-검증**의 3단계 구조를 따릅니다.

```tsx
it('사용자가 로그인에 성공하면 환영 메시지를 보여준다', async () => {
  // 1. Arrange (준비): 컴포넌트를 렌더링하고, API를 모킹합니다.
  render(<LoginForm />);
  
  // 2. Act (실행): 사용자의 행동을 시뮬레이션합니다. (@testing-library/user-event 사용)
  await userEvent.type(screen.getByLabelText('이메일'), 'test@example.com');
  await userEvent.click(screen.getByRole('button', { name: '로그인' }));
  
  // 3. Assert (검증): 실행의 결과로 화면에 나타난 변화를 확인합니다.
  expect(await screen.findByText('환영합니다!')).toBeInTheDocument();
});
```
